# 推断与边界

## H14 基础输入的观察一致性

**置信度：高（限于已执行输入）。** 完整 trace 中的 37 条输入均唯一对应基础组
`.seq` 的 37 行，且 1,656 个逐步输出全部与 H14 DOT 相同。因此，这批运行支持
“H14 基础组在该运行环境中没有出现可观察的 Mealy 输出反例”。它不证明真实 AMF
只具有有限状态，也不证明未执行的额外短环路线、被排除 `s2` 或未观察输入上的
行为。

## 退出码 134 的可能机制

**置信度：中等。** 日志中 43 次 UPF 端口占用、NG context 已移除、认证重传发送
失败及线程销毁断言，说明相邻序列的核心停止/重启没有完全隔离。参考 v2.6.6
源码与后两条 AMF 日志字符串相符：已失效的 RAN 上下文使下行认证请求发送返回
`OGS_NOTFOUND`，随后认证状态机的重传路径期望 `OGS_OK`。不过实际核心二进制、
`start_core.sh` 的运行时版本均未冻结，并且脚本哈希已明确不匹配；这不是源码级
根因结论。

## 不采用 `statelearner_trace.cleaned.jsonl`

**确定的分析规则。** cleaned 文件本身只有 498 行，而完整 trace 有 1,656 行，
不能代表完整运行。它可能适合人类浏览或运行器内部筛选，但从现在起不得作为
模型核对、环覆盖计数、重复轮次对齐或寄存器候选推断的输入；这些结论只读取
`statelearner_trace.jsonl`。
